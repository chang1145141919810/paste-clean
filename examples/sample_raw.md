#三个方案对比

**核心结论：**先上线最小版本，再补数据和权限。

##方案一：直接复用现有模块##

现有模块已经覆盖了
大部分场景，所以不用重写。**注意**：接口的 `timeout` 要
单独设，不然会拖慢整体响应。

### 优点
- 改动小
- 上线快

### 缺点
- 扩展性一般
  - 后续加字段要改两处
    1. 数据库
    2) 接口层
    3、前端表单

***

## 方案二：新写一层适配

| 维度 | 方案一 | 方案二 | 说明 |
|:---|:---:|---:|---|
| 开发量 | 3 人日 | 8 人日 | 只算主流程 |
| 风险 | 低 | 中 |
| 可扩展 | 一般 | 好 |

｜维度｜方案一｜方案二｜
｜上线时间｜下周一｜下月中｜

```python
def handle(req):
    # 这里保留缩进和空行

    if req.timeout > 3:
        return fallback(req)
    return call(req)
```

参考 [接口文档](https://example.com/api) 和 `retry` 参数。

======

最后：**不要**在
第一期就做权限拆分。
